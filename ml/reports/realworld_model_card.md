# ProvenanceX real-world model card

> **REAL-WORLD DATA, SMALL SAMPLE. Rows come from sandboxed scans of public repositories at pinned revisions. Labels: known_vulnerable from reviewed GHSA/OSV advisories (established); benign from metadata criteria (no advisory for that version, verified publisher or signed release, minimum age), which is not ground truth. 'unknown', suspicious and malicious rows are excluded. The task is benign vs known_vulnerable: it is not malware detection. Synthetic data is not used here.**

Generated by `ml/scripts/train_realworld.py`.

- Task: benign vs known_vulnerable, per artifact type, only where real data suffices.
- Models: Random Forest (primary), XGBoost (comparison), Isolation Forest (fit on benign train rows only).
- Runtime: software scans load `ml/models/realworld/software` only when its SHA-256 digests verify and the quality gates pass (`REALWORLD_MODELS_ENABLED`); otherwise they fall back to the synthetic models with ML kept out of the decision band. Model, LoRA, dataset and malicious artifacts stay on rules + REVIEW.
- Artifacts: software under `ml/models/realworld/`.

## Results (test split)

- software: RF F1 0.885, ROC-AUC 0.633, FPR 1.000 vs rules-only F1 0.885, FPR 1.000 (test n=29).
- software runtime quality gates: fail, not loaded: labelled rows 147 < 150; test rows for benign 5 < 30; test rows for known_vulnerable 24 < 30; ROC-AUC 95% CI lower bound 0.2946 is not > 0.5.

## Not supported

- model: no model; fewer than 15 usable rows for: benign, known_vulnerable (rule-based / REVIEW fallback kept)
- lora: no model; fewer than 15 usable rows for: benign, known_vulnerable (rule-based / REVIEW fallback kept)
- dataset: no model; fewer than 15 usable rows for: benign, known_vulnerable (rule-based / REVIEW fallback kept)
- confirmed_malicious: 296 registry packages, metadata only by owner decision; no feature rows, so no malicious-class model. Malware stays with rules + REVIEW.
- suspicious: no record carried a Hub 'unsafe' flag in this collection; no class.
- Hugging Face: no advisory database exists for Hub repositories, so no model, LoRA or dataset can be known_vulnerable; benign HF models exceeded the 600 MB scan budget.
- unknown: 166 manifest rows failed the benign criteria and are excluded (missing evidence is not benign).
- known_vulnerable labels the package's own code; the scanner's vulnerability features describe dependencies, so the label may not be visible in the features (see the label evidence check per model).
- Benign is criteria-based, not ground truth: a package with an undisclosed flaw can pass.
- Every real row is a first scan: hash/config/graph comparison features are null (no_prior_scan); behavior features are null while the dynamic sandbox is disabled.
- Seeds are popular projects and advisories are recent: the sample is not representative of all packages.
