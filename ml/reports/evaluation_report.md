# ProvenanceX evaluation report

> **WARNING: SYNTHETIC DATA: every number in this report comes from generated fixtures and controlled tampering. It does not measure detection of real-world attacks.**
>
> Labels are true by construction, and the features come from the same recipes that assign the labels. Scores therefore show whether the pipeline can recover the signals that were injected, not how it would perform on real packages or models. Benign and tampered records overlap by design, not because that overlap was observed. No real malware was used, so malicious_known_bad has no records and no result here is a malware-detection claim. "Any risk" means any non-benign label, and vulnerable does not mean malicious. Advisories, CVSS values and sandbox traces are generated. Do not cite these numbers as real-world accuracy.

Generated by `ml/scripts/evaluate_models.py`. Do not edit by hand.

## Threshold policy

Primary results use the saved models and the thresholds already chosen on validation. Retraining experiments (repeated splits, ablation, leave-one-recipe-out) pick a threshold on their own validation split by the same procedure, with the same fixed hyperparameters. No threshold or hyperparameter was changed after seeing test results.

## The vulnerable label

vulnerable_count nearly determines the vulnerable label, so the rules baseline is expected to do well on that class. Good results on that class are not evidence that the models learned anything beyond a lookup of that one feature.

| Measured on all records with the feature | Count | Share |
|---|---|---|
| Vulnerable-label records with `vulnerable_count` > 0 | 351 / 351 | 1.000 |
| Records with `vulnerable_count` > 0 that carry the vulnerable label | 351 / 701 | 0.501 |

Records with advisories that also had a more severe recipe applied carry that more severe label, so count > 0 alone does not imply the vulnerable label.

Measured baseline results on the vulnerable class (primary test split). Compare these with the expectation above:

| Baseline | Precision | Recall | F1 | ROC-AUC | FPR | FNR |
|---|---|---|---|---|---|---|
| Vulnerability-only baseline | 0.491 | 1.000 | 0.659 | 0.898 | 0.204 | 0.000 |
| Rules-only baseline | 0.853 | 0.500 | 0.630 | 0.742 | 0.017 | 0.500 |

The rules baseline predicts the most severe class among the rules that fired, so a vulnerable record where a static or behavior rule also fires is predicted suspicious. The vulnerability-only baseline predicts vulnerable for every record with advisories, including those that carry a more severe label.
